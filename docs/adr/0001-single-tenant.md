# 单租户边界

脚手架及其客户项目均为单租户系统：一次部署只服务一个客户组织，数据模型不含租户标识。多租户被显式排除——若某个客户项目需要多租户，必须在立项时以新的 ADR 重新决策，不允许以补丁方式追加租户列。

**Considered Options**: SaaS 多租户（共享库+租户列，或独立库/独立 schema）——被拒。所有已交付项目均为面向单一运营商客户的数据系统；多租户会引入贯穿全部查询的过滤复杂度而没有当前收益，且事后追加租户列会污染既有查询语义。

**Consequences**: 新增模块的表设计不得预留「通用 tenant 字段」；任何「加一列租户就支持多租户」的提议都违反本决策，必须先推翻本 ADR。
