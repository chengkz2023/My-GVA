# 模板复制维护模式

客户项目从脚手架仓库复制出独立副本，各自演化；脚手架的修复以 cherry-pick 方式按需回流到客户项目。不将脚手架抽成共享 npm/go 包，也不维护「分叉 + 定期整体合并」的关系。

**Considered Options**: 共享库分发——被拒。脚手架跨越前后端与目录约定（模块生成器、架构测试、构建配置、种子数据），包化只能覆盖其中一小部分，却迫使所有客户项目锁定同一版本，升级耦合高于收益。

**Consequences**: 脚手架改动不承诺向后兼容客户项目的业务代码；`CHANGELOG.md` 是客户项目判断「自己基于哪个版本」的唯一依据，版本发布必须更新它。
