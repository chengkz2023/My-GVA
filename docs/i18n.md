# i18n 接缝与错误码契约

## 前端 i18n 接缝

- vue-i18n v11 已接入：`web/src/i18n/index.js`，默认 locale `zh-CN`（fallback 同），已在 `main.js` 注册。
- **规则：新增 UI 文案一律走 `t()`**。示范页：`view/superAdmin/dictionary/dictionary.vue`（全部文案来自语言包）。
- 存量硬编码中文**不抽取**（见 `CONTEXT.md`「多语言接缝」）。有海外交付需求的项目：在 `web/src/i18n/index.js` 追加语言包、增加 locale 切换，并自行抽取该项目的存量文案。

## 后端错误契约

响应统一结构：

```json
{ "code": 0, "message": "ok", "msg": "ok", "data": {} }
```

- `code == 0` 成功；非 0 失败。
- `message`/`msg` 是**人类可读文案**（当前中英混排，仅用于展示与日志），**不是契约**——前端逻辑必须基于 `code` 或 HTTP 状态码判断，禁止解析文案。
- HTTP 状态码语义：`400` 校验失败 / `401` 未登录或凭证失效 / `403` 无权限 / `404` 不存在 / `409` 冲突 / `429` 限流（登录防爆破）/ `500` 内部错误（文案固定为 `internal error`，不泄漏细节）。
- 已登记的业务 code：`7`（通用业务失败，与具体语义解耦——所有 `platform/errors` 的 `WithMessage` 错误在未指定 code 时都用它）。
- 需要前端区分错误种类的场景：后端应在 `platform/errors.Error` 上指定稳定的业务 code，并**在本文件登记**（当前登记表：`7` = 通用失败）。

## 多语言对后端的影响

- 后端返回中文文案不阻塞出海：海外项目按上述契约，前端按 code 渲染本地化文案（可用语言包覆盖「需要展示的后端文案」，或在后端错误处直接改用英文文案）。
